# Kintex-7 贪吃蛇项目原理说明讲稿

## 0. 开场

大家好，我这次介绍的是一个基于 Verilog、运行在 Kintex-7 FPGA 开发板上的贪吃蛇游戏项目。

这个项目不是单纯把蛇画在屏幕上，而是把一个完整小游戏拆成多个硬件模块来实现，包括 VGA 显示、游戏状态机、按键和 PS/2 键盘输入、随机食物生成、分数显示、暂停菜单、死亡画面和历史最高分。

录制时可以先展示最终效果：上电进入 `SNAKE!` 开始界面，可以选择 Easy、Normal、Hard 三档难度，标题周围有一条小蛇按当前难度速度移动；进入游戏后可以控制蛇移动、吃食物得分；按 Esc 可以打开暂停菜单；死亡后显示 `GAME OVER` 和最终分数，按确认键回到主菜单。

## 1. 项目总体结构

这个工程的核心代码在 `rtl` 目录下，主要模块可以分成五类：

1. 顶层集成模块：`snake_top.v`
2. 显示相关模块：`vga_controller.v` 和 `snake_render.v`
3. 游戏逻辑模块：`snake_game.v`
4. 输入与外设模块：`debounce.v`、`ps2_keyboard.v`、`seven_seg_display.v`
5. 辅助模块：`clk_div.v`、`lfsr.v`

可以把整个系统理解成一条数据流：

`按键/键盘输入` 进入 `snake_game`，更新蛇的位置、食物、分数和状态；这些游戏状态再送给 `snake_render`，由它决定每一个 VGA 像素应该显示什么颜色；同时分数送到数码管，状态送到 LED。

整个设计使用一个 100MHz 主时钟，低速逻辑没有另起时钟，而是使用 clock enable，也就是时钟使能脉冲。这样可以避免多个时钟域带来的同步问题。

## 2. 时钟与节拍设计

项目的输入时钟是开发板上的 100MHz 时钟。

`clk_div.v` 主要生成两个使能信号：

- `vga_ce`：约 25MHz，用来驱动 VGA 像素扫描
- `game_tick`：基础游戏节拍，硬件上大约 5Hz，也就是每 200ms 一次

VGA 显示需要稳定、连续地扫描像素，因此它使用更高频的 `vga_ce`。而贪吃蛇移动不能太快，所以游戏逻辑只在 `game_tick` 到来时更新一次。

难度不是通过改变时钟实现的，而是在 `snake_game.v` 里用 `move_div_cnt` 对基础 tick 再分频：

- Easy：基础 tick 除以 4
- Normal：基础 tick 除以 2
- Hard：直接使用基础 tick

这种方式的好处是所有逻辑仍然在同一个 100MHz 时钟域下运行，只是不同模块根据使能信号决定什么时候更新。

## 3. 顶层模块 snake_top

`snake_top.v` 是整个设计的连接中心。

它完成几件事：

1. 处理上电复位和外部复位
2. 实例化时钟分频模块
3. 对板载按键进行消抖
4. 接入 PS/2 键盘
5. 合并实体按键和键盘输入
6. 实例化游戏核心 `snake_game`
7. 实例化 VGA 时序和渲染模块
8. 驱动数码管和 LED

这里有一个设计细节：实体按键和键盘方向信号是 OR 合并的。例如 `dir_up = btn_up || kb_up`。所以玩家既可以用开发板按键，也可以用 PS/2 键盘控制，两套输入不会冲突。

## 4. 输入系统：按键和 PS/2 键盘

实体按键是低电平有效，也就是按下时引脚为 0。RTL 里先用 `~BTN[i]` 翻转成高电平有效，再送入 `debounce.v`。

消抖模块的作用是避免机械按键抖动造成一次按键被识别成多次。它会连续采样一段时间，只有信号稳定后才输出一个单周期的 `btn_press` 脉冲。

PS/2 键盘由 `ps2_keyboard.v` 解析。PS/2 协议是一帧 11 位：

1. 起始位
2. 8 位数据，低位先传
3. 奇校验位
4. 停止位

模块在 PS/2 时钟下降沿采样数据，收到完整扫描码后输出单周期脉冲。方向键是扩展码，例如右方向键是 `E0 74`，普通 WASD 和 Enter、Space、Esc 则是普通扫描码。

当前控制方式是：

- 方向键或 WASD 控制移动
- Enter / Space / BTNX4 用于开始和确认
- Esc 用于打开或关闭暂停菜单
- R 键不再执行重启

## 5. 游戏核心状态机

游戏核心在 `snake_game.v` 中实现。

状态机有四个主要状态：

- `S_MENU`：开始界面
- `S_PLAYING`：游戏进行中
- `S_PAUSE`：暂停菜单
- `S_DEAD`：死亡画面

状态切换逻辑大致如下：

```text
MENU --确认键--> PLAYING
PLAYING --碰撞--> DEAD
PLAYING --Esc--> PAUSE
PAUSE --Cancel--> PLAYING
PAUSE --Restart--> PLAYING，并重置蛇身和分数
PAUSE --Exit--> MENU
DEAD --确认键--> MENU
```

这里特别要说明的是死亡状态。现在死亡后不会自动返回主菜单，而是停留在 `GAME OVER` 画面，显示最终分数。只有按下确认键后，才回到主菜单。这更适合演示和实际游玩，因为玩家可以看清自己的最终得分。

## 6. 蛇身存储方式

贪吃蛇的身体用两种结构同时表示：

1. FIFO 风格的坐标数组：`snake_x[]` 和 `snake_y[]`
2. 40×30 的占用网格：`grid_reg`

坐标数组记录蛇身从尾到头的顺序，靠 `head_idx` 和 `tail_idx` 形成环形队列。每次移动时：

1. 根据当前方向计算新头坐标
2. 把新头写入数组和网格
3. 如果没有吃到食物，就删除旧尾巴
4. 如果吃到食物，就保留尾巴，相当于蛇变长

`grid_reg` 的作用是快速判断某个格子是否已有蛇身。这样自碰检测只需要查新头位置对应的 bit。

这里有一个边界问题：如果蛇头正好移动到当前尾巴所在格子，而这一帧尾巴也会前进，那么这不是自碰。代码里通过 `moving_into_tail` 识别这种情况，避免误判，也避免把新头所在格错误清掉。

## 7. 方向控制与连续按键修复

方向控制里有一个容易出错的点：蛇不能 180 度掉头。

最初只用一个 `next_dir` 来保存即将执行的方向。这样在一个移动 tick 之前，如果玩家快速按两次方向键，比如当前朝上，先按右，再按下，第二次输入可能会基于已经排队的“右”来判断，于是“下”被认为合法。可实际蛇还没有真正转向，当前身体仍然在头的下方，所以这会导致下一步直接撞到自己。

现在的实现使用两个方向寄存器：

- `current_dir`：上一次真正移动时提交的方向
- `next_dir`：下一次移动要使用的方向

方向输入合法性始终相对 `current_dir` 判断，而不是相对已经排队的 `next_dir` 判断。这样就能保持“最后一个相对当前实际运动方向有效的输入”。

举例来说：

当前蛇头朝上，玩家先按右，再按下：

- 右相对上是合法的，所以 `next_dir` 更新为右
- 下相对当前实际方向上是反向，所以被忽略
- 下一帧蛇向右移动，不会死亡

这个逻辑在 testbench 中也有专门的回归测试。

## 8. 食物和随机数

食物位置由 `lfsr.v` 提供伪随机数。

LFSR 是线性反馈移位寄存器，硬件实现非常轻量，不需要真正的随机源。项目中使用 16 位 Galois LFSR，不断产生新的伪随机值。

食物坐标由 LFSR 的部分 bit 映射到 40×30 网格：

- X 坐标范围是 0 到 39
- Y 坐标范围是 0 到 29

如果候选位置刚好和蛇身重叠，就不生成食物，等待下一个周期再尝试。这样保证食物不会出现在蛇身内部。

## 9. 分数和历史记录

分数使用 BCD 格式保存，也就是每 4 bit 表示一个十进制数字，最多显示 0000 到 9999。

这样做的好处是数码管和 VGA 显示都可以直接取每一位数字，不需要额外做二进制转十进制。

历史最高分按难度分开保存：

- `high_easy_reg`
- `high_normal_reg`
- `high_hard_reg`

当游戏死亡或者从暂停菜单选择 Exit 退回主菜单时，会把当前分数和对应难度的历史分数比较，如果更高就更新。

## 10. VGA 显示原理

VGA 显示分成两个模块：

1. `vga_controller.v` 负责产生扫描时序，包括 `hsync`、`vsync`、当前像素坐标和有效显示区域
2. `snake_render.v` 根据当前像素坐标和游戏状态决定 RGB 颜色

屏幕分辨率是 640×480，游戏网格是 40×30，所以每个格子正好是 16×16 像素。

渲染时先把像素坐标转换成网格坐标：

```verilog
cell_x = pixel_x[9:4];
cell_y = pixel_y[9:4];
```

这相当于除以 16。因为 16 是 2 的幂，所以用位切片就能完成，硬件代价很低。

渲染优先级大致是：

1. 非显示区域输出黑色
2. 菜单界面
3. 暂停菜单
4. 死亡画面
5. 游戏边框和 HUD
6. 食物
7. 蛇头
8. 蛇身
9. 网格线和背景

死亡画面中，`GAME OVER` 和最终 `SCORE` 会覆盖在暗红背景上，蛇身和食物仍以死亡色调显示，画面更有反馈感。

## 11. 开始界面与标题小蛇

开始界面包括：

- 标题 `SNAKE!`
- 当前难度选择
- 当前难度最高分
- 三档历史记录
- 闪烁 START 提示
- 标题周围环绕运动的小蛇

标题小蛇不是普通图片，而是按照 16×16 网格路径生成的。它和游戏内蛇使用相同风格：蛇头蓝色、身体绿色。

小蛇沿一个闭合矩形轨道运动，并且速度跟随当前选择难度：

- Easy 最慢
- Normal 适中
- Hard 最快

之前左上角曾经出现身体断裂，原因是路径闭环处漏了一个格子，同时某些角点重复。现在路径改成连续闭环，testbench 还会检查整圈相邻点的曼哈顿距离都为 1，避免以后再出现断裂。

## 12. 暂停菜单

暂停菜单由 Esc 打开，状态进入 `S_PAUSE`。

菜单有三个选项：

- `RESTART`：直接重新开始当前难度
- `CANCEL`：返回游戏
- `EXIT`：退出到主菜单，并记录最高分

菜单选择由 `pause_select` 保存，方向键可以上下或左右切换。按 Enter、Space 或 BTNX4 确认当前选项。按 Esc 等同于 Cancel。

这里没有做二次确认，是为了操作更直接。Restart 会立即重置蛇身、食物和分数。

## 13. 死亡画面

死亡画面是这次项目中的一个重要用户体验点。

当发生撞墙或自碰后，状态切换到 `S_DEAD`，`game_over` 输出为 1。

此时：

- VGA 显示 `GAME OVER`
- 下方显示最终 `SCORE`
- LED[1] 点亮表示已死亡
- 游戏不会自动返回主菜单
- 按确认键后才返回主菜单

这样录制演示时，可以停留在死亡结果上，让观众看清最终分数。

## 14. 数码管和 LED

数码管由 `seven_seg_display.v` 驱动，显示当前 BCD 分数。

它通过动态扫描方式依次点亮 4 个数码管位。因为扫描频率很高，人眼看到的是 4 位同时亮。

LED 用来快速观察系统状态：

- LED[0]：游戏中
- LED[1]：死亡
- LED[2]：心跳灯
- LED[3]：菜单中
- LED[4:5]：当前难度
- LED[6]：分数是否大于 0
- LED[7]：game_tick 脉冲

调试硬件时，LED 很有用。例如如果 LED[2] 不闪，说明系统时钟或复位可能有问题。

## 15. 仿真验证

项目提供 `sim/snake_tb.v` 做行为仿真。

仿真里用 `defparam` 把 `GAME_TICK_DIV` 从硬件的 20M 级别缩短到 99，也就是把游戏 tick 从 200ms 加速到约 1us。这样不需要等很久就能看到蛇移动、死亡、菜单切换等行为。

testbench 覆盖了这些关键场景：

- 上电进入菜单
- PS/2 方向键切换难度
- Enter 进入游戏
- R 键不会再打开菜单
- Esc 打开暂停菜单
- Restart / Cancel / Exit 三个暂停选项
- 死亡后停在 Game Over，确认后回主菜单
- 衔尾移动不会误删蛇身
- 连续方向输入不会排入反向方向
- 标题小蛇轨道连续闭环

录制时可以简单展示仿真命令：

```bash
iverilog -o snake_tb rtl/*.v sim/snake_tb.v
vvp snake_tb
```

如果使用 Vivado，也可以把 `snake_tb.v` 设置为仿真顶层，运行 Behavioral Simulation。

## 16. 上板演示建议

录制演示时可以按下面顺序操作：

1. 上电，展示 `SNAKE!` 开始界面
2. 切换 Easy、Normal、Hard，强调标题小蛇速度也跟着变化
3. 按确认进入游戏
4. 控制蛇移动，展示蛇头蓝色、蛇身绿色
5. 吃到食物后展示分数增加
6. 按 Esc 打开暂停菜单
7. 分别说明 Restart、Cancel、Exit 的作用
8. 故意撞墙，展示 `GAME OVER` 和最终分数
9. 按确认回主菜单
10. 最后展示 LED 状态和数码管分数显示

## 17. 总结

这个项目的核心价值在于，它把一个看起来简单的小游戏完整拆解成了 FPGA 上的多个硬件模块：

- 用状态机管理游戏流程
- 用网格和环形队列管理蛇身
- 用 LFSR 生成随机食物
- 用 VGA 扫描逻辑逐像素渲染画面
- 用消抖和 PS/2 协议处理输入
- 用数码管和 LED 扩展硬件交互
- 用 testbench 验证关键边界情况

从系统设计角度看，它覆盖了数字电路课程里很多重要主题：时序逻辑、组合逻辑、状态机、外设协议、显示时序、伪随机数、硬件调试和仿真验证。

这就是本项目的整体原理说明。
